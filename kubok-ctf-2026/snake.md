# Snake

## Summary

Задача — набрать длину, равную числу клеток на шестиугольном поле радиуса 4. Жадный поиск еды может загнать змею в собственное тело; решение — заранее пройти все 61 клетки по гамильтонову циклу. Категория: game/misc; сложность средняя; инструменты: Python и WebSocket-клиент.

## Solution

### Идея и решение

Поле задаётся координатами `(q, r)`, для которых `max(|q|, |r|, |q+r|) <= 4`. Подсчёт даёт 61 клетку. На графе поля клетки — вершины, соседние клетки — рёбра. Гамильтонов цикл посещает каждую вершину ровно один раз и возвращается в начало.

`cycle.py` ищет такой цикл DFS-поиском с эвристикой: сначала пробуются клетки с меньшим числом свободных соседей. `win_fast.py` содержит найденный цикл и таблицу соответствия шести направлений смещениям `(q, r)`. На каждом ходе змея идёт в следующую клетку цикла; благодаря сохранению порядка тела этот маршрут не пересекает собственное тело.

### Результат и проверка

Архив предыдущего решения сообщает, что цикл прошёл игру за 1060 ходов, серверный ответ содержал `won: true`, длина достигла 61; получен флаг:

```text

```

`[из предыдущего подтверждённого прогона; повторный сетевой запуск не выполнялся]`

Важная деталь: `win_fast.py` обращается к турнирному WebSocket-сервису. Здесь его не запускаю и не предлагаю использовать повторно: живость инстанса и правила турнира в этой проверке не подтверждались. Локального сервера игры в каталоге нет.

### Почему жадный подход ломается

Кратчайший путь к текущей еде оптимизирует только ближайший ход. Он не учитывает, что после роста тела часть клеток станет недоступной. Гамильтонов цикл вместо локальной оптимальности даёт глобальную гарантию посещения всего поля.

Термины: **граф** — вершины и связи между ними; **DFS** — поиск в глубину с возвратом при тупике; **гамильтонов цикл** — замкнутый маршрут через каждую вершину ровно один раз; **WebSocket** — двунаправленное соединение поверх HTTP.
