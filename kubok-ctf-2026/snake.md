# Snake

## Summary

Поле игры — шестиугольник радиуса 4 с 61 клеткой. Вместо поиска пути к очередной еде строим гамильтонов цикл по всему полю и на каждом ходе идём в следующую вершину цикла. Так голова никогда не врежется в тело, а игра неизбежно заполняет поле.

## Solution

Клетку представим осевыми координатами `(q, r)`. Допустимые клетки удовлетворяют `max(abs(q), abs(r), abs(q + r)) <= 4`; направления `0..5` соответствуют смещениям `(1,0), (1,-1), (0,-1), (-1,0), (-1,1), (0,1)`.

Граф содержит 61 вершину. Цикл можно найти DFS: из текущей клетки перебираем непосещённых соседей и сначала выбираем вершины с наименьшим числом ещё свободных соседей. Условие завершения: последняя вершина должна быть соседом стартовой.

Для проверки я получил следующий цикл, начиная с `(0, 0)`:

```text
1512344211133535340533504550000133332151500011222234055542432
```

Это строка направлений. После `reset` сервер начинает в `(0, 0)`, поэтому достаточно повторять эту строку направлений по кругу и после каждого хода ждать новое состояние.

Ключевая часть клиента выглядит так:

```python
cycle = "1512344211133535340533504550000133332151500011222234055542432"
ws.send(json.dumps({"type": "reset"}))
state = json.loads(ws.recv())
for direction in itertools.cycle(map(int, cycle)):
    ws.send(json.dumps({"type": "move", "dir": direction}))
    state = json.loads(ws.recv())
    if state.get("won"):
        break
```

Еда может появляться в произвольной клетке, поэтому длина растёт не на каждом обходе, но порядок перемещения остаётся безопасным.

Проверка цикла: он содержит 61 переход, каждая вершина лежит внутри поля, соседние вершины различаются на одно допустимое смещение, а последний переход ведёт обратно в `(0, 0)`. В турнирном запуске сервер вернул `won: true` при длине 61.
