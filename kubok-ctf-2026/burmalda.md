# Burmalda

## Summary

В игре на Godot достижение целевого баланса открывает панель с флагом. Флаг не нужно получать игровым процессом: он зашифрован прямо в скрипте, а функция декодирования использует константы и линейный генератор состояния. Категория: reverse; сложность лёгкая-средняя; инструменты: GDRE Tools, Python 3.

## Solution

### Разведка

Исходный PCK уже восстановлен в `work/recovered/`. Лог GDRE сообщает:

```text
Successfully loaded PCK!
Verified 18 files, no errors detected!
```

`[из сохранённого лога извлечения]`

Ищем функцию выдачи флага:

```bash
rg -n '_decode_flag|_EF|_SA|_SB|_LC|_LA|_target_enc' work/recovered/main.gd
```

`_EF` — байты шифротекста; `_SA`, `_SB`, `_LC`, `_LA` — константы; `_decode_flag()` показывает преобразования и точный порядок операций.

### Декодирование

Для воспроизведения достаточно уже извлечённого GDScript:

```bash
python3 work/solve_flag.py
```

На каждом индексе `i` скрипт обновляет 32-битное состояние:
`state = (LC * state + LA) mod 2^32`. Байтом потока становится `(state >> 13) & 255`. Затем выполняются XOR с `_EF[i]` и вычитание индекса по модулю 256.

```text
ctfcup{Сначала_ДЭП_Потом_Додэп_Потом_ласт_Дэп_потом_Ультра_Ласт_Дэп_и_всё_будет_чётко!}
codepoints=87 utf8_bytes=151
```


Проверка длины в кодовых точках и UTF-8-байтах полезна из-за кириллицы: число символов и количество байтов здесь различаются.

### Почему это работает

Скрытие флага за условием «накопить баланс» — только интерфейсный барьер. Если приложение содержит и шифротекст, и ключевые константы, клиентское условие можно обойти анализом. Генератор состояния детерминирован, поэтому повторение нескольких арифметических операций возвращает тот же поток байтов.

### Воспроизведение и границы

Чтобы повторить извлечение самого проекта, нужен GDRE Tools и исходный `Burmalda.pck`; готовая распаковка уже лежит в `work/recovered/`. В этой проверке воспроизводился декодер флага из извлечённого скрипта, а не игровой процесс.

Термины: **PCK** — контейнер ресурсов Godot; **32-битное переполнение** — отбрасывание результата выше младших 32 бит; **UTF-8** — кодировка Unicode, где символы могут занимать разное число байтов.
